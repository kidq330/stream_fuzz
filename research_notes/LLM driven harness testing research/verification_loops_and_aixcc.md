## Key Question 1 — Spec inference, contract generation, and Dafny/Verus/Lean "LLM writes, verifier judges" loops: what success rates, what failure modes?

### Takeaway
On small, self-contained tasks the LLM+verifier loop now routinely clears 80–96% in Dafny (DafnyBench 68% in 2024 → ~96% by late 2025), ~40–90% in Verus depending on benchmark difficulty, and <10–30% in Lean; the dominant known failure mode is not proof failure but **spec quality**: verification-passing specs are frequently incomplete, vacuous, or co-adapted to the code, and several 2025–2026 benchmarks (CLEVER, Verina, AlgoVeri, vericoding) were explicitly designed to close that loophole.

### Cited Findings

**Benchmarks and loop results (Dafny)**
- DafnyBench (Loughridge et al., arXiv 2406.08467, TMLR 2025): 782 Dafny programs (~53k LOC); task = LLM regenerates stripped annotations until Dafny verifies. Claude 3 Opus 67.8% ±1.7, GPT-4 Turbo 59.8% ±1.8, GPT-4o 59.3% ±1.8, GPT-3.5 Turbo 44.0% ±1.8; best models ~54% on first try, plateau ~65% by n≈5 attempts **[search-summary]** — [DafnyBench PDF](https://namin.seas.harvard.edu/pubs/dafnybench.pdf); [TMLR listing](https://mlanthology.org/tmlr/2025/loughridge2025tmlr-dafnybench/); repo exposes a `--feedback_turn 3` verifier-feedback loop and no explicit anti-cheating check is documented in the README **[primary]** — [sun-wendy/DafnyBench](https://github.com/sun-wendy/DafnyBench)
- DafnyPro (arXiv 2601.05385, Jan 2026): Claude Sonnet 3.5 + DafnyPro reaches 86% on DafnyBench, +16 pp over the base model **[search-summary]** — [alphaxiv 2601.05385](https://www.alphaxiv.org/abs/2601.05385)
- Vericoding benchmark (Beneficial AI Foundation / Tegmark group, arXiv 2509.22908; presented at Dafny 2026 workshop @ POPL 2026; "under ICLR review"): 12,504 formal specs (3,029 Dafny, 2,334 Verus, 7,141 Lean), 6,174 "new unseen" problems; off-the-shelf LLM success 82% Dafny, 44% Verus, 27% Lean; adding natural-language descriptions did not significantly improve results; they report pure-Dafny verification progressing "from 68% to 96% over the past year" **[search-summary]** — [arXiv 2509.22908](https://arxiv.org/abs/2509.22908); [Tegmark announcement](https://x.com/tegmark/status/1973769931184644180?lang=en); [POPL 2026 Dafny workshop page](https://popl26.sigplan.org/details/dafny-2026-papers/13/A-benchmark-for-vericoding-formally-verified-program-synthesis). Repo: tasks are specs that compile "up to some `sorry` or `assume false`", a separate `issues/` folder holds non-compiling specs, `vericoding_results_v1.csv` holds 55,397 experiments, and `experiments/inspection/` holds manual quality inspection reports **[primary]** — [Beneficial-AI-Foundation/vericoding](https://github.com/Beneficial-AI-Foundation/vericoding)
- Clover (Sun, Sheng, Padon, Barrett; SAIV 2024 / Dafny'24 @ POPL 2024; arXiv 2310.17807): reduces correctness checking to *consistency checking* among code, docstring and Dafny annotations; CloverBench = 60 hand-written Dafny programs incl. adversarial incorrect variants; acceptance rate up to 87% on correct instances with zero false positives (gpt-4-1106-preview, March 2024; repo defaults to gpt-4o) **[primary README + search-summary]** — [ChuyueSun/Clover](https://github.com/ChuyueSun/Clover); [Clover paper PDF](https://theory.stanford.edu/~barrett/pubs/SSP+24.pdf); [POPL'24 Dafny talk](https://popl24.sigplan.org/details/dafny-2024-papers/1/CLOVER-Closed-Loop-Verifiable-Code-Generation)
- Follow-ons (titles only, numbers unverified): AxDafny "Agentic Verified Code Generation in Dafny" (arXiv 2606.32007); ATLAS "Automated Toolkit for Large-Scale Verified Code Synthesis" (arXiv 2512.10173); BRIDGE (arXiv 2511.21104); Goedel-Code-Prover hierarchical proof search (arXiv 2603.19329); Vero "Can AI Agents Build Formally Verified Software Repositories?" (arXiv 2608.13522) — [AxDafny](https://arxiv.org/pdf/2606.32007); [ATLAS](https://arxiv.org/pdf/2512.10173); [Vero](https://arxiv.org/pdf/2608.13522)

**Benchmarks and loop results (Verus / Rust)**
- AutoVerus (Microsoft; arXiv 2409.13082; ICLR 2025 per Lahiri): three-phase loop (inference → refinement → repair) driven by Verus error output; VerusBench = 150 tasks (11 CloverBench, 78 MBPP, 38 Diffy, 23 Verus-tutorial misc); proves 137/150 = 91.3% **[primary README for composition; search-summary for 91.3%]** — [microsoft/verus-proof-synthesis](https://github.com/microsoft/verus-proof-synthesis); [arXiv 2409.13082](https://arxiv.org/pdf/2409.13082). Lahiri's blog adds that AutoVerus "uses soundness/completeness metrics to filter LLM-generated Rust/Verus specifications and proofs" and achieved 3.6× the proof accuracy of GPT-4o zero-shot **[primary]** — [RiSE blog](https://risemsr.github.io/blog/2026-03-05-shuvendu-intent-formalization/)
- AlphaVerus (CMU L3; arXiv 2412.06176): self-improving translation (Dafny→Verus), "Treefinement" tree search over verifier feedback, and an explicit **Filtering/Exploit-Model** stage "to prevent reward hacking by filtering misaligned specifications and programs" — i.e., the authors treat spec gaming as a first-class threat; no model fine-tuning **[primary README]** — [cmu-l3/alphaverus](https://github.com/cmu-l3/alphaverus); a later comparison reports AlphaVerus at "53 tasks of 150 (24.9%)" on VerusBench **[search-summary; note 53/150 is 35.3%, so one of the two figures in that snippet is wrong — treat as unverified]** — [search source: AutoVerus/ExVerus/KVerus listings](https://arxiv.org/pdf/2603.25810)
- VeruSAGE (arXiv 2512.18436, Dec 2025): agentic observation-reasoning-action loop for *systems-level* Verus proofs; repo describes 849 repository-level benchmarks; o4-mini reaches 41% on VeruSAGE-Bench vs AutoVerus 20% on
